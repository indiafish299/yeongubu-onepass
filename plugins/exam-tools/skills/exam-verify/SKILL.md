# 시험지 검증 (exam-verify)

결과는 **선생님 PC 로컬**(`~/.exam-tools/work/<이름>/`)에만 둔다. 시험지·정답·보고서 내용을 메신저·드라이브·메일로 보내지 않는다. 밖으로 알릴 때는 「검증 끝남」 한 줄만.
보고서는 통과 도장이 아니다. 최종 판정은 선생님과 교과 협의회.

- 파이썬: `~/.exam-tools/venv` (윈도우 `…\venv\Scripts\python.exe`, 맥 `…/venv/bin/python`)
- 명령: `<PYTHON> -B "<SKILL_DIR>/engine/exam_verify/cli.py" <명령>` (`<SKILL_DIR>` = 이 파일이 있는 폴더)
- `~/.exam-tools/profile.json` 이나 venv 가 없으면 **exam-setup 부터** 한다. 있어도 시작 전에 exam-setup 의 `doctor.py check` 로 로그인만 확인한다.

## 순서 (관문 둘은 건너뛰지 않는다)

1. **시험지 PDF.** 입력은 한글에서 뽑은 PDF 하나(인쇄본과 줄 배치가 같다).
   - 선생님이 `.hwp` 를 주면: 윈도우는 `pdf <원안.hwp> <work/이름/input.pdf>` (한글 자동화, 창을 띄우지 않음). 맥은 `engine/tools/hwp2pdf.sh --allow-front …`(뷰어 창이 10~15초 앞으로 나오므로 먼저 묻는다) 또는 선생님께 한글에서 PDF 저장을 부탁.
   - 원본은 건드리지 않는다. 고친 시험지는 새 이름으로 처음부터 다시(`--prev <지난 이름>`로 견줌).
   - `rhwp export-pdf` 는 보기 번호를 빠뜨리니 입력으로 쓰지 않는다.
2. **준비:** `prepare <이름> <PDF>` — 쪽 이미지를 만들고, 학교명·출제자·실시일자·결재란·저작권 줄을 **자동으로 찾아 가린다**(글자 층이 없으면 `--mask "쪽:x0,y0,x1,y1"` 로 손으로). 정답 형광 표시(노랑)도 지운다.
   경고(「가린 뒤에도 남은 이름」, 「노란 형광」)가 나오면 그 쪽을 직접 본다.
3. **관문 1 — 보내도 되는지:** `box/` 의 가린 이미지(두 쪽씩 묶어 보여 드리면 편하다)와 `text.txt`(교정 단계에 보낼 글자 층)를 선생님께 보여 드린다.
   학교·이름이 다 가려졌고 문항은 안 가려졌는지 확인받고, 다른 회사 AI 로도 보낸다는 것을 함께 말한다. 「보내도 됨」을 받은 뒤에만 `approve <이름>`. 이미지가 바뀌면 승인은 무효.
4. **관문 2 — 정답표:** exam-paper 의 「…정답_배점표.md」가 있으면 `answers <이름> <md>` 로 읽어 표로 보여 드리고, 선생님이 눈으로 확인한 뒤에만 `answers <이름> --confirm`.
   md 가 없으면 선생님께 정답을 받아 `{"confirmed": false, "answers": {"1": "②"}}` 꼴로 `work/<이름>/answers.json` 에 쓰고 똑같이 확인받는다. 서답형 채점 기준은 `rubric.md` 로.
   md 의 「범위」 줄은 `scope.txt` 로 저장돼 run 이 그대로 쓴다(없으면 `--scope "1학년 통합과학 ○단원~○단원"`).
5. **돌리기 전 한 줄:** `plan <이름>` — 검토자, 호출 수, 걸리는 시간(30~60분), 남은 한도. Claude 한도는 `mcp__ccd_session_mgmt__get_usage`. 한도가 빠듯하면 검토자를 줄이는 안(`--models`)을 말씀드린다.
6. **실행:** `run <이름>` 을 **백그라운드**로(30분~1시간). 맥은 터미널 탭(`mcp__terminal__run_in_terminal`)에서 돌린다(앱 셸에서는 claude 가 로그인 안 됨으로 보일 수 있다). 터미널에 한글 인자를 넣을 수 없으면 실행 스크립트 파일을 만들어 부른다.
   모델 하나가 빠지면 「검증 불완전」. 같은 run 을 다시 돌리면 빠진 것만 이어 돈다(한도 오류로 멈춘 경우도).
7. **보고:** `work/<이름>/report.html` 을 선생님 PC 에서 연다(윈도우 `Start-Process`, 맥 `open`). 맨 위 「한눈에」 세 줄을 그대로 전하고, 「꼭 다시 볼 문항」부터 함께 본다.
   지적은 교과서 표기 그대로인지 확인하고(교과서 표기면 고치지 않음), 고칠지는 선생님이 문항별로 정한다.
8. **지우기:** 선생님이 「지워」라고 할 때만 `purge <이름> --yes`.

## 검토자

- `profile.json` 의 검토자(exam-setup 이 요금제에 맞춰 고름)를 쓴다. Claude 만 있으면 페이블·오푸스 둘, ChatGPT·Gemini 가 있으면 솔·네온이 더해진다.
- 반박은 같은 지적을 하지 않은 모델이 맡는다 — 다른 회사 모델을 먼저, 없으면 같은 회사 다른 모델.
- 모델은 끝까지 정답을 보지 못한다. 대조는 스크립트가 한다. 채점 기준표는 마지막 단계에서만 보여 준다.
- 격리: 모델마다 `box/` 폴더에서 돌고, 실행 기록의 도구 호출을 검사해 `box/` 밖을 읽거나 명령·웹을 쓰면 그 실행은 「격리 위반」으로 버린다.
- `--fast` 는 낮은 추론 단계(가짜 시험지 시험용). 실제 시험지에는 쓰지 않는다.

## 알아 둘 것 (실제로 겪은 것)

- **오탈자는 교정 단계가 잡는다.** 이미지만 보여 주면 모델들이 「자연선택셜」을 고쳐 읽고 놓쳤다. 글자 층이 없는 PDF(스캔본)나 글자 층 승인이 없으면 이 단계는 건너뛰고 「검증 불완전」. 그림 속 글자·수식은 글자 층에 없을 수 있다.
- **큰 오류가 같은 문항의 작은 흠을 가린다.** 그래서 고친 뒤에는 바뀐 문항만이 아니라 전체를 다시 돌린다.
- 원안의 정답 형광펜은 종이 인쇄에는 안 나오지만(한글 인쇄 기본값) **PDF 로 저장하면 찍힌다.** prepare 가 지우지만, 다른 색·밑줄로 표시한 정답은 못 지우니 `box/` 를 직접 본다.
- 모델마다 지적 성향이 다르다(어떤 모델은 혼자 내는 지적이 많고 대부분 반박된다). 여러 모델이 함께 짚은 지적부터 본다.
- 가짜 시험지로 처음부터 끝까지: 윈도우 `engine/tests/run_fake.ps1`, 맥 `engine/tests/run_fake.sh`.
